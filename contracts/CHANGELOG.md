# Contract changelog
- 2026-09-06 v1.0.0 — initial schemas (panel, projects, findings, models, briefs, model_card), enums, fixture.
- 2026-09-07 v1.0.0 — golden fixtures projects.sample.json / findings.sample.json committed (Task 9).
- 2026-09-09 v1.0.0 — golden findings.sample.json regenerated (no schema change). Only the generated assistant answers moved: Q2 now separates 'cannot reach the stated date at its own pace' from 'the stated date has already passed' instead of reporting both as one number, and Q5 now states the multiples-of-5 and multiples-of-10 shares on the same denominator as the expectation it is compared with (whole numbers).
- 2026-09-09 v1.1.0 (task 21) — minor, additive. `findings.schema.json`: `meta.headline` gains `contradictions_arithmetic` and `statistical_anomalies` (both required) so the rule-based arithmetic count and the M4 isolation-forest anomaly count are named separately and never blended into one total; `meta` gains a required `denominators` object (`cost_revised_null`, `cost_overrun_null`, `doc_null`) so a null share on screen can be traced to its base; `field_audit` gains `whipple_index` and `whipple_band` (both required, nullable) for F5's digit-heaping check. `projects.schema.json`: `$defs/Flag` gains optional `first_snapshot` (string or null) and `occurrences` (integer), populated only on the display-collapsed flag lists returned by the new `findings.collapse.collapse` — not added to `Flag`'s required array, so raw (uncollapsed) flag objects remain valid. Golden fixtures `contracts/fixtures/projects.sample.json` and `contracts/fixtures/findings.sample.json` regenerated to match: `findings.run.build_projects` now renders collapsed flags (fewer rows, each carrying `first_snapshot`/`occurrences`) while `risk.score` and `build_findings` keep scoring and counting the raw, uncollapsed flag list.
- 2026-09-09 v1.2.0 (task 23) — minor, additive. `findings.schema.json`: new required object `delay_series` (`bands`: array of band names; `rows`: one entry per snapshot with `on_schedule`, `d_1_12`, `d_13_24`, `d_25_60`, `d_61_plus`, `classifiable`, `doc_null`, all required integers) reconstructs the delay-band counts the April 2014 Flash Report printed and later reports stopped printing, recomputed from `doc_original`/`doc_revised` against the April 2014 report's own band edges (1-12, 13-24, 25-60, 61+ months). Golden fixture `contracts/fixtures/findings.sample.json` regenerated to include the new `delay_series` block.
- 2026-09-09 v1.3.0 (parser epoch-date fix) — minor, additive. `enums.json`: `parse_flag` gains `EPOCH_DATE`. The Flash Reports themselves print `01/1900` in the date columns for 11 projects (July 2026 page 76 shows it for GMC Handwara 707052, GMC Leh 707057, GMC Gondia 706988, GMC West Garo Hills 706989 and GMC Mon 707067, among others) — the source spreadsheet's zero date, not a month anyone entered. `parser.normalize.parse_dates` now returns NULL for a token printed in year 1900 and records `EPOCH_DATE` on the row, so `doc_original`/`start_month` are NULL rather than a date ~1500 months in the past. `DATE_PARSE_FAIL` keeps its old meaning (no unparenthesised month could be read at all), so the two remain distinguishable. Affects 22 panel rows across 2026-06 and 2026-07.
